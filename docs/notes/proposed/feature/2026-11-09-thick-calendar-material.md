# Agent Note: Thick Calendar Material

Status: proposed

## Problem

纯白日期卡片与外围毛玻璃之间的质感差异较大，需要在保留小字号可读性的同时比较更柔和的透色层次。

## Proposal

月视图、年概览和设置页共用常驻的 SwiftUI thickMaterial 背景，外围继续使用 AppKit popover 材质。背景独立于正文托管视图和快照，随既有卡片几何更新，避免过渡绘制覆盖实色白底。关闭毛玻璃时统一恢复实底。年份行不再独立绘制底色，直接复用其下方的卡片背景；小月历绘制时裁剪年份行当前覆盖区域，滚动通知触发重绘，保留对下方日期、悬停反馈和焦点环的遮挡。独立提取的缩放标题快照仍保留完整文字。

灰色背景下仅更换厚材质仍难以区分卡片与外围，因此浅色模式叠加半透明白色提亮，并为材质卡片增加轻阴影，参数由[日历参考](../../../calendar-reference.md)拥有。浅灰背景下弱白色叠层不足以拉开明度，因此提高白色覆盖而不继续加重阴影，代价是减少背景透色。深色模式不叠加白色；关闭毛玻璃时不增加阴影。背景复用的责任和年份遮挡由[共享内容背景](../../implemented/simplification/2026-11-09-shared-content-surface.md)拥有。背景托管范围为阴影预留空间，卡片实际尺寸不变。

此试用重新评估[弹窗材质](../../implemented/feature/2026-10-23-popover-material.md)的实色日期区选择，保留[圆角日期区](../../implemented/feature/2026-10-24-rounded-calendar-surface.md)的尺寸与裁剪，以及[常驻外壳](../../implemented/bug-fix/2026-10-24-persistent-calendar-chrome.md)的容器生命周期。待手动确认视觉方向后再决定是否正式采用。

## Alternatives considered

- 保留实底：对比度稳定，但无法减轻纯白块的视觉割裂。
- 只更换材质档位：灰色背景下两层明度仍可能接近，不能稳定建立边界；采用提亮与轻阴影补足。
- 薄材质：透色更强，对密集农历与事件文字的背景干扰也更明显，先比较厚材质。
- 在年份行重复叠加同样材质：即使参数相同，二次合成仍会产生色差；让年份行露出共享背景，并裁掉被其覆盖的月份内容。
- 把材质放进正文快照：快照不能完整保留窗口服务器的实时背景合成，且可能在动画交接时跳变。

## Acceptance criteria

在浅色、深色和彩色桌面背景下手动比较日期与事件文字可读性、卡片边界、月年切换、设置往返及快速返回；年份行上下底色连续，滚动日期不穿透标题；关闭毛玻璃后恢复实底，系统减少透明度仍由系统材质处理。此次按用户要求构建试用包、检查差异并运行年概览与设置专项冒烟，不运行完整冒烟或更新展示图；正式采用前补足相关界面验证。

## Risks

提亮与阴影的强度仍需在不同桌面背景下比较；年份悬浮遮挡需要随滚动及时重绘，跨年推顶和缩放快照需保留覆盖。材质合成和动画交接的视觉效果尚待真实桌面手动确认，编译不能证明这些表现。
