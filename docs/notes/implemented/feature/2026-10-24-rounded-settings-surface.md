# Agent Note: Rounded Settings Surface

Status: implemented

## Problem

设置页的整页灰底、独立分组卡片与常驻滚动条，与主页面的外围材质和单块圆角内容区偏差明显。用户确认的设计稿要求统一视觉层级，同时保留原有偏好、滚动和固定操作入口。

## Decision

设置区独立实底现由[共享内容背景](../simplification/2026-11-09-shared-content-surface.md)取代，本文其余布局决定保持有效。

设置页移除自己的不透明根背景，复用展示控制器已持有的系统材质及实色回退。正文采用与日历一致的实色底、圆角和外边距；分组以留白和细线表达，顶部左对齐标题与胶囊返回按钮呼应月份标题和导航，底部保留固定退出入口。

继续使用 SwiftUI 的原生滚动、菜单选择器和开关，仅定制菜单按钮标签及按钮样式。滚动指示器使用 `never`，使圆角面板在系统设置为始终显示滚动条时也保持完整；`hidden` 仍可能受系统偏好影响。菜单采用支持自定义标签的按钮样式，避免无边框菜单重新绘制标签而丢失胶囊外观。保持系统键盘与辅助功能语义，不自建菜单或开关状态机。

所有偏好继续由 CalendarView 的 AppStorage 拥有，设置页只消费绑定，假期更新仍由原模型负责。共享 CalendarShell 在替换为设置内容前记录日历高度；设置页沿用这一高度，中间滚动区填满标题与底栏之间的剩余空间。高度测量属于视图，不写入日历模型或持久化偏好，也不反向测量设置页以免产生尺寸反馈循环。动态日期格式、更新结果和展开说明只影响中间滚动内容，不推挤返回和退出入口；返回日历后恢复按当前日期详情测量。共用外壳与往返形变由[设置容器过渡](2026-10-24-settings-container-transition.md)拥有。

此决定部分取代[分组设置](2026-10-23-grouped-settings.md)的多卡片表面与[弹窗材质](2026-10-23-popover-material.md)的设置页独立背景，保留两者原有的偏好所有权、信息分组与系统外观适配理由。

## Alternatives considered

- 只缩小原来的卡片和间距：仍保留与主页面不同的整体结构，无法消除整页灰底带来的割裂。
- 引入独立设置窗口或多页标签导航：增加导航成本，当前选项规模仍适合单面板滚动。
- 设置页使用独立固定高度：446 pt 会使常见月视图进入设置时变高；只改成与年概览相同的 430 pt，仍无法覆盖月视图随详情变化的高度。沿用入口高度避免扩大改动到日历详情布局。
- 自绘开关和菜单：可精确控制像素，但需额外维护键盘、焦点及辅助功能行为，原生控件已满足当前设计。

## Consequences

设置首屏可见项数随打开前的日历高度变化，放假安排、关于信息和较长更新结果可以滚动查看。显示日期格式、展开说明或切换偏好不改变本次设置页面的高度；返回日历时若偏好改变了日期详情长度，日历仍按其原有规则调整高度。

真实入口冒烟验证普通日期、节气与假期详情以及年概览进入设置时的尺寸保持、滚动条隐藏、滚动与固定返回入口、开关绑定和返回选择，并生成深浅色、材质开关、长格式、展开说明及更新消息快照。视图位图不能完整呈现窗口服务器合成的背景模糊；实际桌面透色、VoiceOver 和不同系统版本仍需人工体验。
