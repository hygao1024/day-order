# Agent Note: Calendar Mode Cycling

Status: implemented

## Problem

日程图标需要直接循环切换四档，不再通过菜单选择；隐藏时不应触碰系统日历权限，恢复上次的非隐藏偏好也不能遗漏授权申请。该决定部分取代[系统日程展示](2026-11-06-system-calendar-events.md)中的菜单交互和仅手动选择时申请权限，保留事件读取、绘制与布局边界。

## Decision

单个原生按钮按详细、精简、圆点、隐藏、详细的顺序切换，图标、提示与旁白说明当前及下一档。顺序由显示模式拥有，按钮直接调用生产控制器，不再保留原生菜单或菜单协调器。

隐藏模式在检测权限之前返回，清空投影并使在途查询失效。非隐藏模式在切换、恢复偏好和正常刷新时读取实际权限；尚未决定和仅写权限自动请求完整访问，完整访问不重复申请。系统已拒绝或限制访问时无法重复显示系统授权窗，只在恢复已启用的偏好或用户主动切到非隐藏模式时提示打开系统设置，不因切月或后台通知反复提示；刚拒绝授权窗后不立即追加设置提示，避免连环弹窗。权限提示不改变原有面板布局。

已开始的系统授权任务可以完成，但所有消费者仍经过代际与取消检查；迟到事件返回后，先判断请求是否仍有效，再做权限复查，避免隐藏后又开始权限检测。

切档时的正文缩放、重定向与取消由[日程模式缩放](2026-11-06-calendar-mode-animation.md)拥有；本记录继续拥有按钮顺序和权限边界。

## Alternatives considered

- 保留菜单并增加循环快捷操作：存在两个选择入口，偏离一次点击直接换档的需求。
- 只在点击时请求权限：应用恢复已保存的非隐藏模式时仍可能因缺权限而空白。
- 隐藏模式也检测权限：不服务当前展示需求，并扩大了用户关闭日程后的系统访问范围。
- 拒绝后反复调用系统授权接口：macOS 不会再次展示授权窗，不能让用户完成恢复；提供系统设置入口更直接。

## Consequences

静态图标和日期格布局沿用已有实现，事件获取及状态检查继续由同一控制器拥有。顺序测试覆盖两轮循环；短的真实按钮专项覆盖各档权限检测、自动请求、隐藏时零检测、快速切档与迟到结果，操作系统边界使用隔离数据。

本次交付按用户要求不运行完整界面回归，真实系统授权和账户同步由打包后的应用实机验证。后续完整回归继续复用同一个生产按钮入口。
