# Agent Note: Popover Material

Status: implemented

## Problem

用户希望月历采用 Apple 原生毛玻璃效果，中间日期区保留白底的清晰度，以及已经优化的年概览滚动表现。

## Decision

中间日期区的实色选择正在由[厚材质试用](../../proposed/feature/2026-11-09-thick-calendar-material.md)重新评估；当前试用实现以该记录及代码为准，本文保留原实色方案的理由。年份行独立底色由[共享内容背景](../simplification/2026-11-09-shared-content-surface.md)取代。

月视图与年概览的上下固定区域共享 NSVisualEffectView 的 popover 材质，以 behindWindow 模式取样窗口后方背景。移除根视图的不透明灰底，设置页原先单独保留背景，此部分现由[统一设置页面](2026-10-24-rounded-settings-surface.md)取代，设置页外围也使用共享材质。中间日期区按用户最终选择恢复为浅色白底、深色深灰底，不叠加透明材质；上下保留原生毛玻璃，不添加提亮遮罩。年概览的列表与滚动视图透明，共用一层固定实色背景。浮动年份标题使用同一底色，避免日期从标题下方穿透；上下分隔线减淡。材质位于内容后方，不参与鼠标命中和辅助功能导航。

此决定部分取代[年概览](2026-10-23-year-overview.md)的上下灰阶表面。系统拥有模糊、深浅色与减少透明度适配，不增加权限、依赖或后台任务。设置“显示”分组提供“毛玻璃效果”开关，默认开启以保留既有外观；CalendarView 通过 AppStorage 持久化 blurEnabled，设置继续绑定同一偏好，展示控制器读取它以更新共享背景。关闭时显示原有实色灰底；材质实例的跨页面保留由[常驻日历外壳](../bug-fix/2026-10-24-persistent-calendar-chrome.md)接管；系统“减少透明度”仍优先决定开启状态下的最终合成效果。

## Alternatives considered

- 给整个视图应用 blur：会模糊日期文字与控件，不能实现背景材质。
- 自行截图并进行高斯模糊：需要处理截图权限、桌面变化与持续刷新，系统已有相应合成能力。
- 整个弹窗使用同等透明度的材质：背景可能影响小字号农历和节日文字的可读性，因此日期区使用实色底色。
- 淡灰底、轻微透色和上下提亮遮罩：用户体验后仍偏好原来的白底，因此恢复实色白底与原生上下材质。

## Consequences

原有上下直线边界通过叠加带实色底的细线避免透明接缝，并覆盖末行横线以避免重复叠色；仅降低独立分隔线的不透明度不能解决接缝透色。边界布局现由[月视图圆角日期区](2026-10-24-rounded-calendar-surface.md)与[年概览圆角设计](2026-10-24-rounded-year-overview.md)取代，仍保留实色内容底与系统材质的职责分离。

月视图与年概览共用一个常驻材质实例，连接顶部、底部和圆角内容区外边距，滚动行不创建视觉效果视图。真实入口快照检查布局、深浅色文字和交互，滚动基准检查主线程处理开销；视图位图快照无法完整捕获窗口服务器的背景合成，透色和减少透明度效果仍需桌面体验。不同系统版本及桌面背景可能产生不同通透程度。
