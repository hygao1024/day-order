# Agent Note: Soft Agenda Surface

Status: implemented

## Problem

日程详情与选中日期属于同一日历上下文，分别维护固定浅灰色、深色提亮和实色回退，会让两者在外观或底层材质变化时呈现不同底色。

## Decision

沿用[精简日程卡片顶部](2026-11-10-agenda-compact-header.md)的纯圆角容器。日期正常选中状态与日程详情共同读取 `CalendarSurface.selectionBackgroundColor`，使用系统主文字色的低透明度填充，不绘制详情外边框和阴影。共享颜色使用动态系统色，不提前解析为固定 RGB 值；两处都在外观变化时重绘。日期按下的临时加深反馈仍由日期按钮拥有，不传给详情。具体参数由[日历参考](../../../calendar-reference.md#系统日历日程)拥有。

背景左右边缘对齐日期网格首末列的选中底边缘，正文位置、宽度与周行高度不变。详情不再维护独立深浅色分支、减少透明度回退或为此新增的通知观察者；毛玻璃开关和减少透明度沿用外层背景，两处填充自然透出相同底层。圆角与填充在同一绘制入口完成，真实列表与既有周行快照保持一致。

## Alternatives considered

- 固定浅色 RGB 值、深色单独提亮：能固定单一浅色画面，但无法与动态的日期选中底色持续保持一致。
- 在两处重复同一颜色表达式：当前效果相同，后续调色容易漂移，因此共享颜色定义。
- 外边框或阴影：背景填色已经表达分组，额外装饰突出容器，阴影还需要独立绘制留白；仅保留日程之间的内容分隔线。
- 内嵌独立模糊材质：重复已有合成层，且窗口服务器实时材质与展开快照可能出现视觉差异。
- 浅色叠加白色提亮：外层厚材质已经偏白，继续提亮会让日程呈现独立白色面板感。

## Consequences

空状态与有日程状态使用同一种背景，列表交互和数据来源不变。背景最终像素随系统外观和底层背景变化，不再保证固定 RGB 值。深浅色真实视图快照可比较选中日期与详情填色，但不证明真实桌面透色或辅助功能开关的全部动态表现；此前日程专项尺寸与位置断言失败的原因尚未定位，后续通过不代表该不稳定性已消除。
