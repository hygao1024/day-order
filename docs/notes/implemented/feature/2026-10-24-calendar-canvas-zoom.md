# Agent Note: Calendar Canvas Zoom

Status: implemented

## Problem

逐日轨迹能连接月历与小月历，却让周围月份停在原地并淡出。用户要求以选中月份为焦点，整张日历画布一起缩放和平移，周围月份随放大移出视口，缩小时反向进入。两种页面的字号、日期行距与详情密度并不成比例，单纯等比放大无法精确落到月视图布局。

## Decision

完整正文交叉淡化和逐帧矢量背景绘制现由[单份日历日期网格](../bug-fix/2026-10-25-single-calendar-date-grid.md)部分取代。焦点日期只绘制一份，并随共享进度连续展开行距；背景按最大显示尺寸预绘制。本文保留整张画布相机与邻月运动的理由。月视图进入年概览时的焦点选择由[可见面积决定缩放月份](../bug-fix/2026-10-25-visible-month-zoom-focus.md)拥有。

展示层用年概览作为共享坐标系。两端可见且未被浮动年份标题遮挡的同日锚点只用于求解焦点与横向比例；相机持有唯一的等比缩放、平移及速度。整个年概览正文，包括邻月、月份标题、星期、日期与今天红圈，共同使用该变换，删除逐日位置、字号、字重与透明度轨迹。日期选择、月份导航和滚动位置仍由原模型与列表拥有。

日历正文使用原生视图生成的 PDF 矢量快照，显示时按相机变换绘制，避免放大低分辨率位图。仅捕获当前视口，不缓存全年内容。月视图快照通过终点变换的逆映射放进同一坐标系；缩放接近月端点时，以整块正文渐显衔接详细布局，农历、节日和补位日期随之出现。详情交接消费空间位置而非重启后的墙钟时间，因此反向时跟随相机自然逆转；主要运动阶段保持年画布完整。

事件长标题的透明度遮罩与日历图标由[事件细节绘制](../bug-fix/2026-11-06-event-title-pdf-mask.md)在局部位图内预合成，避免 PDF 回放出现黑块或丢失符号镂空；整体画布仍使用本记录的快照路径。

[完整月历端点](../bug-fix/2026-11-06-complete-month-zoom-snapshot.md)将月端点改为按逻辑视口逐周采集并合成，避免旧年概览窗口裁掉末周；年端点与相机运动保持不变。

现有控制器继续负责准备修订号、单一显示刷新驱动、圆角视口、外壳和清理。月年保留 400 ms 无回弹弹簧，容器与相机在重定向时只换目标，保留位置和速度。相同月份的画布在短暂进入设置时保留并继续运动，通过独立透明度淡出；及时返回可接续原相机。普通设置往返仍交叉淡化正文。减少动态效果或缺少可用焦点时，整块内容使用短淡化，不能凭空构造缩放端点。

此决定部分取代[连续日历运动](../bug-fix/2026-10-24-continuous-calendar-motion.md)的逐日轨迹及月年正文固定时间淡化；其弹簧节奏、上下栏淡化、月份索引缓存和取消责任继续适用。也取代[日期缩放过渡](2026-10-24-calendar-zoom-transition.md)与[显示同步缩放](../architecture/2026-10-24-display-synchronized-calendar-zoom.md)中仅日期参与缩放的边界，保留原生页面和显示同步机制。

## Alternatives considered

- 继续逐日插值并添加邻月轨迹：运动事实仍散落在独立元素上，难以保证所有月份保持同一个空间关系，也扩大重定向状态。
- 将原始小截图整体放大：方向正确，但文字和圆圈会放大模糊；采用原生矢量快照。
- 将年概览非等比拉伸到月视图行距：可以对齐日期中心，却会拉长字形和红圈；保留等比相机，在月端点附近整体交接两种布局。
- 修改常态月历或年概览布局，使所有间距严格成比例：会改变四至六周月份、文字大小和信息密度，超出转场需求。

## Consequences

画布成本随当前可见内容增长；每次过渡结束或关闭即释放。重定向保留当前画布与最多两张通用正文图，不积累页面历史。靠近月端点的短交接可能同时看到两种日期布局，这是保留原有行距和等比缩放的取舍。

真实入口采样实际绘制矩形，检查选中月和邻月的等比关系、相对位移、缩放幅度、矢量来源与详情交接，并保存不同阶段快照。覆盖四至六周、闰年二月、星期起始、日期上下界、自由滚动恢复、连续反向、设置插入、关闭、减少动态效果及不可见端点。负向控制把绘制矩形固定在年端点，必须触发画布缺少缩放检查。物理屏幕帧率、不同刷新率和操作手感仍需桌面体验。
