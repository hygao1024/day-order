# Agent Note: Holiday-cn Schedule

Status: implemented

## Problem

用户现在需要中国大陆放假和补班标记，并选择 holiday-cn 作为数据源。节日名称和日期本身不能推导年度调休安排，未来年份的空占位文件也不能解释为没有假期。

## Decision

采用内置已核对快照、用户手动联网更新、年度本地缓存。年度文档保留公告链接，事实来自上游对国务院公告的整理。界面独立显示休班角标，不改变既有节日分类；完整数据范围与操作契约由 README 拥有。

核心模块拥有数据验证与按年合并，HolidayRepository 拥有网络读取和缓存写入；应用模型拥有更新任务及可观察状态，退出时取消任务。失败不破坏当前数据，空占位或无效数据不写缓存。一次更新只执行一个任务，当前年与翌年分别报告结果。网络使用系统代理配置，不内置本机代理或密钥。

读取当前年份及相邻年份的缓存，按年度修订号防止较早的缓存读取覆盖刚完成的联网更新，更新期间仍可加载其他年度缓存。下一年通知中对本年十二月的明确记录优先。缺失数据保持未知，不推算上游省略的连休周末。既有离线历法与节日计算保持原样；本决定扩展了[原生离线日历记录](../architecture/2026-10-23-native-offline-calendar.md)中的网络边界。

## Alternatives considered

- 每次展开联网查询：数据新鲜，但让轻量日历依赖网络可用性。
- 仅随应用更新数据：最简单且完全离线，但年度安排发布后用户必须更新整个应用。
- 依据周末及往年规律推算：无法可靠推导补班及政策变化，可能误导用户。
- 自动后台更新：减少操作，但当前没有必要引入后台调度、重试与静默失败状态。

## Consequences

联网能力只用于明确的手动更新；源码保留 MIT 许可与固定快照校验和。允许第三方源更新，因此结构校验不能代替对公告的语义核对。普通周末不打休班标记，缺失安排可见。日期、跨年、无效输入、失败保留缓存和取消通过测试；联网和真实界面通过生产入口冒烟验证。不同 macOS 版本及旁白操作尚需人工覆盖。
