# Agent Note: Arrowless Calendar Panel

Status: implemented

## Problem

菜单栏日历使用 NSPopover 自动生成指向图标的箭头，用户要求改为无箭头外观。公开接口没有隐藏箭头的开关，窗口承载的替换必须保留日历输入、外部点击关闭与动态尺寸。

## Decision

以 CalendarPanel（NSPanel 子类）替代 NSPopover，使用透明无边框窗口与圆角内容裁剪，保留现有展示控制器、常驻材质及月年和设置过渡。展示控制器通过内容尺寸回调驱动面板尺寸；面板拥有图标锚定、屏幕边界限制及关闭监听，AppDelegate 继续拥有日历键盘语义和过渡取消。

尺寸更新在内容布局回调内执行，因此只提交窗口边界，不要求同步绘制；由正常显示周期完成布局和绘制。同步绘制会重入 AppKit 的旧窗口约束，先恢复旧高度，再以错误的顶部为基准调整新高度，造成顶部向上或向下偏移一个详情高度差。不能用稍后再次定位掩盖可见跳动。

面板打开时注册局部与全局鼠标监听、应用失活、图标窗口位置和显示环境通知；关闭时先移除监听，再隐藏窗口并通知页面清理。图标点击留给原有开关动作，面板及其子窗口和原生弹出菜单的点击不触发外部关闭。屏幕布局或桌面空间切换时关闭，下次打开重新定位，避免保留失效锚点。

此决定部分取代[原生离线日历](../architecture/2026-10-23-native-offline-calendar.md)中的系统气泡窗口生命周期；不改变日期模型、偏好和资源边界。

## Alternatives considered

- 保留 NSPopover 并调整内容：箭头由系统外框绘制，调整 SwiftUI 内容不能可靠去掉它。
- 使用私有箭头属性或修改系统内部视图：依赖未公开实现，系统升级可能失效。
- 自定义 NSPanel：需要显式维护关闭、尺寸与定位，但只使用公开 AppKit 接口，能完整表达无箭头面板。

## Consequences

新增窗口生命周期代码替代系统气泡提供的行为，关闭清理和菜单交互成为必须验证的边界。真实应用专项冒烟检查无边框尺寸、切月与详情高度改变过程中的顶部锚定、重复开关、Esc 和内外事件分流；原有页面回归继续覆盖设置、偏好和动画。合成事件与视图快照不证明跨应用物理点击、所有显示器布局、全屏空间或所有 macOS 版本，覆盖范围由[无箭头面板验证](../../../../README.md#无箭头面板验证)维护。
