# Agent Note: Menu Bar Panel Opacity Transition

Status: implemented

## Problem

菜单栏图标打开和关闭面板时直接出现、消失。用户希望整窗淡入淡出，并保留快速点击时的连续性。原关闭回调会立即清空日程和内部动画，若在仍可见的淡出中执行，会使内容先于窗口突变。

## Decision

在 [CalendarPanel 的窗口生命周期](2026-10-29-arrowless-calendar-panel.md)内维护打开意图、当前窗口透明度和短暂的淡化状态。禁用窗口附加的原生开关动画，使用已有显示刷新目标逐帧更新 NSWindow 的透明度，全程不另建内容快照、不缩放或移动窗口；完整打开 140 ms、关闭 90 ms，采用三次缓出。反向从已经显示的透明度起步，剩余时长按距离缩短；重定向先停止旧驱动，回调校验当前驱动身份，避免取消后的旧回调覆盖新状态。

关闭意图立即使 `isShown` 为 false，停用窗口内鼠标和日历键盘处理，但在淡出完成前保留内容与关闭通知监听。真正隐藏后移除监听并通知 AppDelegate 清理日程、内部过渡和键盘监控；重复关闭不重启淡化，也不重复清理。淡出期间再次打开保留当前页面，不执行今日复位；完全隐藏后重新打开继续遵守[回到今天](2026-10-23-reopen-today.md)的规则。

屏幕或桌面变化、应用退出直接停止驱动并隐藏，避免依赖失效屏幕的下一帧；减少动态效果时直接到达目标，运行途中开启也在下一帧结束。释放面板时移除监听并作废驱动。显示刷新遵循系统默认调度，静止后没有持续回调，无新增偏好或依赖。

## Alternatives considered

- 先触发原关闭清理再淡出：会使日程或设置内容在淡出中变化，无法连续反向。
- 关闭时截取整窗快照：引入额外采样、材质冻结与交接成本，现有真实窗口即可合成透明度。
- 仅提交不可中断的动画及延时隐藏回调：快速重开时需防止旧完成回调隐藏新窗口，且难以直接接续当前已显示透明度；复用现有刷新驱动可由同一状态拥有绘制与结束。
- 反向时立即回到今天：页面和尺寸会在尚可见的淡出过程中跳变，因此今日复位仅在完全隐藏后的新会话执行。

## Consequences

`isShown` 表示开关意图，`isVisible` 表示窗口是否仍在屏幕上；关闭完成的消费者和测试必须等待真正隐藏。Esc 层级和窗口定位继续由原有所有者负责，日历内部动画样式不变。专项覆盖真实窗口透明度、反向、减少动态效果、显示环境变化、完成和取消后的回调停止，原面板及日程重开验证覆盖清理时机；验证入口与覆盖限制见[界面验证参考](../../../verification.md#无箭头面板)。
