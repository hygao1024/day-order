# Agent Note: Year Overview Scroll Performance

Status: implemented

## Problem

用户反馈年概览连续滚动卡顿。外层表格虽复用行，行内仍需替换 SwiftUI 根视图、布局两个日期栅格。固定滚动基线出现明显主线程耗时尖峰，既有功能和静态截图检查没有覆盖这一成本。

## Decision

保留原生表格和[年概览导航](2026-10-23-year-overview.md)，月份行只持有两个原生按钮，直接绘制月份、星期、日期和今天圆圈；年份行使用原生文字与编辑按钮。删除滚动行内的 NSHostingView 与逐日 SwiftUI 子视图。

概览协调器按年月缓存天数和首日星期，范围最多为支持的 2400 个月，随概览释放。星期起始只影响绘制偏移，今天只影响颜色，不使公历缓存失效。文字字形和尺寸在主线程共享，颜色使用系统动态语义色；悬停仅使对应按钮重绘。NSButton 保留鼠标、键盘焦点与辅助功能动作，复用时更新标签和动作，不保留旧月份的选择目标。

悬停以当前窗口鼠标位置和实际命中视图为准，不能把进入/离开事件当作持久状态：滚动、裁剪和复用可能使通知过期，造成多个灰底残留。按钮在滚动范围、跟踪区域及窗口焦点变化时重新判断，仅状态改变时重绘；离开窗口时解除对应通知，释放时清理观察者。绘制回归在真实概览往返滚动中注入迟到的进入通知，检查最多一个月份有灰底；旧实现会触发多灰底断言。

## Alternatives considered

- 保留 SwiftUI 并仅缓存日期计算：减少少量运算，但不能消除滚动中新行的视图构造与网格布局。
- 将整年转成位图：绘制廉价，但会额外承担缩放、深浅色、今天变化与交互命中的缓存失效；当前固定尺寸的原生绘制已经足够轻量。
- 仅在复用时清空悬停：不能处理仍在可见区域内的旧行；直接取消悬停则会失去月份点击反馈，因此保留反馈并从当前命中结果更新。

## Consequences

年概览行的内部实现由原生视图拥有，布局数值须与设计截图一同维护；设置和月视图的固定区域继续使用 SwiftUI，月视图的日期区域由[连续周滚动](2026-10-24-continuous-calendar.md)接管。引入可重复的固定滚动基准，记录主线程同步处理耗时而非屏幕帧率；以同机同构建配置的前后对比验证效果，避免把机器负载造成的差异固化成易波动测试门槛。真实入口继续检查日期、年份跳转、复用后鼠标点击、辅助功能动作与深浅色截图；完整 VoiceOver 流程及不同设备刷新率仍需人工体验。
