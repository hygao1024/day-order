# Agent Note: Two-row Month Snapping

Status: implemented

## Problem

[月初吸附](2026-10-24-calendar-month-snapping.md)使用固定距离，无法覆盖用户期望的前两行。各月按四至六周均分视口，放大统一点数会让不同月份的吸附范围落在不同周行内。

## Decision

由实际位于视口顶部的行及其月份区块决定吸附目标，月份标题与前两周均回到该月第一周，第三周起点退出该区间。邻月补位日期按所在区块计入周行，不按日期自身月份重新归属。仍处在上一月末尾时，保留接近下一月月初的原有吸附距离。

此决定部分取代原月初吸附的固定距离判定，复用现有月份周索引和原生表格几何，不新增偏好或另一份布局。手势与惯性等待、动画中断、选择与浏览分离和恢复语义继续沿用；具体交互由[日历行为与数据参考](../../../calendar-reference.md)拥有。

## Alternatives considered

- 将固定距离扩大到两行的估算高度：四至六周行高不同，且像素对齐会使相邻行略有差异，不能可靠表达第三行起点的边界。
- 将月初两侧都扩大为两行：会把上一月更大范围的月末阅读位置拉走，超出此次前两行需求；保留月初之前的原有距离。

## Consequences

在第二行停下也会回到月初，用户需要滚过第二行才能停留在月中。真实入口回归覆盖两种星期起始方式下的四至六周、跨年、第二行末尾与第三行起点，并继续验证手势、惯性与取消。旧固定距离实现作为负向控制应在第二行吸附断言失败。合成事件与快照不能证明物理触控板手感或全部系统版本。
