# Agent Note: System Calendar Events

Status: implemented

## Problem

日序需要在月历日期下展示系统日程，提供详细、精简、圆点、隐藏四档，同时保留原有面板宽度、日期信息、底部详情和连续滚动。原有六周月份每行约 48 pt，直接叠加胶囊会覆盖农历或相邻周；用户同意仅为日程增加日期行高。

## Decision

系统日历是事件与账户同步的事实来源。应用层的 EventKit actor（串行隔离执行器）拥有系统句柄和后台查询；独立控制器拥有授权、查询代际、通知与模式偏好。Core（核心层）只接收不可变事件值，负责按设备民用日期归属、半开区间、排序与重复项去重，不接触权限和系统句柄。此边界允许无授权运行真实生产界面验证，也避免把原有历法模型变成账户同步客户端。

默认隐藏，只有主动选择非隐藏模式才请求授权；系统没有只读授权档位，应用只读取。用户选择隐藏或应用退出会使已有查询失效，权限拒绝及撤销清空投影；查询返回后重新检查授权，阻止迟到结果重新显示私有日程。正在进行的系统授权请求由一个共享任务拥有，因为应用无法关闭系统弹窗，切月与模式变化只使旧消费者失效，不重复发起授权。

沿用原生日期按钮绘制和 NSTableView（原生表格视图）复用。显示模式只增加整月的日期区高度，保持每个月四至六周均分、完整显示整月、滚动吸附和原有上下栏。行高变化后先恢复视口，再配置最终可见周行，避免复用视图遗留旧模式或旧旁白内容。图标菜单填入月份标题与导航之间的现有弹性留白，不增加工具栏。隐藏且投影为空时不发布无效刷新，避免独立日程状态干扰原有页面交接；同一轮发生模式切换与显式导航时，以新导航为准，不能恢复旧视口。

本记录部分扩展[原生离线日历](../architecture/2026-10-23-native-offline-calendar.md)关于不接入系统日历的首版范围；离线历法、日期标注与资源规则继续由原记录拥有。

图标菜单和授权触发时机由[日程按钮循环切换](2026-11-06-calendar-mode-cycling.md)部分取代：保留四档绘制及原有布局约束，交互改为单击顺序切换，非隐藏模式恢复时也检查并请求权限。

逐日独立排布由[连续跨日日程](2026-11-06-continuous-calendar-events.md)部分取代；日期归属、权限及面板容量保持本记录的边界。

## Alternatives considered

- 固定原有行高直接叠加事件：六周月份的农历已占用大部分行高，无法保证文字不重叠；只为日程增加行高已获得用户明确授权。
- 在月历下增加日程列表：偏离已确认的日期格内展示范围，并改变原有底部布局。
- 在界面直接传递 EKEvent（系统事件对象）：把可变系统句柄和授权时序泄漏到绘制及历法模块，难以隔离验证。
- 持久化日程缓存或自行连接账户：当前消费者只需展示系统已有日程，会额外引入隐私、失效与同步责任。

## Consequences

原有离线使用无需授权，隐藏模式恢复原有日期区尺寸。系统日程不写磁盘，不引入账户同步或第三方依赖；可通过隐藏模式停止读取。详细模式受可用行数和横条宽度限制，更多事件通过计数及日期旁白标签表达，当前范围不含事件编辑或独立详情列表。

日期归属单元测试与真实应用入口回归覆盖四档绘制、四至六周月份、权限拒绝及撤销、失败恢复、迟到结果、通知刷新与模式切换和导航的组合。权限守卫使用临时绕过检查的负向控制证明拒绝后读取会被真实入口检测到；生产守卫恢复后执行完整回归。程序化跳转必须先进入真实视口，再验证依赖可见月份的年概览焦点，避免以尚未渲染的选择冒充可见月份。

无凭据回归仅替换操作系统权限与事件库边界，不能证明真实账户同步、系统授权弹窗或各日历提供商的所有行为；真实授权需用户从完整应用包操作。静态视图快照不证明桌面背景模糊、物理帧率或完整旁白交互。
