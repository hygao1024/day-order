# Agent Note: Calendar App Icon

Status: implemented

## Problem

原构建脚本现场绘制红白底和「日」字，不能保留已确认设计中的日期点阵、翻页角、挂钩比例和轻微材质层次。

## Decision

采用挂钩内收、主体比例校正后的日历图标，将透明 PNG 保存到 `Assets/AppIcon.png`。构建仅缩放这份源图并通过现有 `iconutil` 流程生成 ICNS（macOS 图标格式），不再用代码重新绘制图形。源图独立于设计迭代目录，普通构建不依赖图像生成服务或开发者个人路径。

正方形画布不能证明可见主体等宽等高。源图检查还需测量主体轮廓和四边留白，忽略轮廓外的低透明度散点；调整轮廓时保留日期圆点和挂钩的比例，避免整体非等比拉伸。生成图片仍可能有微小几何误差，不把它视为按系统模板构造的精确矢量轮廓。

## Alternatives considered

- 用 AppKit（macOS 原生界面框架）重绘：会形成第二份视觉事实，难以精确保持已经确认的材质和比例。
- 仅替换构建目录中的 ICNS：下一次构建会恢复旧图标，不能作为持久方案。

## Consequences

保留现有 macOS 14 起的静态图标兼容性；轻玻璃质感由图片表达，不是系统动态材质或分层图标。菜单栏动态日期继续使用单色模板，与应用品牌图标分工不变。替换源图后需要重新构建；生成器拒绝无法读取、非正方形或不足 1024 像素的源图，避免无效资源进入图标打包步骤。
