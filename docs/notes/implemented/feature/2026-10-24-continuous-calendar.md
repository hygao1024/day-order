# Agent Note: Continuous Calendar

Status: implemented

## Problem

用户确认了连续跨月滚动的设计稿，希望轻滑时日期随手势移动、停在任意位置，同时保留固定的顶部和日期详情。一次手势切换整月不能满足这一交互。

## Decision

中间区域以原生滚动视图和可复用周行替代单月 SwiftUI 网格。核心 CalendarTimeline 只生成轻量的周、月标题索引。各月份分别补齐首尾周，周行显式携带所属月份；边界周允许在相邻区块中各出现一次，所有本月日期在自己的区块中恰好出现一次。首尾范围外留空，不产生可选日期。

沿用[年概览性能优化](2026-10-23-year-overview-scroll-performance.md)的原生按钮绘制方式，按可见周计算农历与节日，缓存最多 128 周并随视图释放。现有显示选项同时供日期区与详情消费，避免出现分类开关不一致。背景继续复用当前表面定义，滚动不触发网络更新。

应用模型分别拥有已选日期、浏览月份和明确导航请求。连续滚动只写浏览月份，日期按钮只写选择；月份导航和“今天”同时发出定位请求。返回设置或年概览按月份区块、日期所在周和周内偏移恢复，避免依赖原生长列表重建后的绝对坐标估算。星期起始改变时重建周序列并保留日期锚点。

滚动通知合并到主线程后续任务，不在 SwiftUI 更新期间发布状态。定位请求使旧通知失效，视图拆除时取消任务并移除通知和表格代理，避免迟到回调覆盖新的导航目标。详细行为与尺寸由 README 拥有。

日期配色以周行所属的月份区块为准，同时比较年和月。邻月补位的数字、农历、节日及休班角标统一使用淡灰色，今天作为补位日期时也不使用红圈；只弱化显示，不禁用点击。顶部年月仅是浏览位置提示，不影响各区块配色。

## Alternatives considered

- 手势阈值翻月或滚动结束吸附：与用户明确要求的自由慢速滚动不符。
- 每个跨月周只保留一份：最初采用，但无法同时呈现十月末的完整周与十一月初的完整周。用户进一步确认按区块区分本月日期和邻月补位后，采用独立月份区块。
- 以顶部年月统一置灰：会把已经进入下一个月份区块的正常日期全部弱化，不符合用户期望。
- SwiftUI 逐日惰性视图：已有年概览暴露了复杂视图构造及远距离定位成本，继续复用原生列表更符合当前性能需求。
- 一次生成全部农历和节日：不影响滚动语义，却增加打开时的计算和内存；仅预建轻量行索引即可。

## Consequences

月份标题位于该月第一周之前；首尾补位仅用于维持七列对齐，邻月日期可以在本月区块与其自身区块中重复出现。定位日期默认进入其自身月份，恢复位置显式携带区块，避免落到另一份补位周。底部详情可以对应当前窗口外的已选日期，滚动不会暗中更改选择。显示范围、逐日连续性和闰日由核心测试覆盖；真实入口检查周内滚动、跨月标题、鼠标与辅助功能选择、设置返回、日期边界、星期起始、深浅色以及现有年概览。触控板的惯性手感和完整旁白流程仍需人工体验。
