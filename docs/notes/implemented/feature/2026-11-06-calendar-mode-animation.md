# Agent Note: Calendar Mode Animation

Status: implemented

## Problem

四档模式原先直接重算日期行高和日期区尺寸，正文会突然替换，无法与现有设置过渡的节奏保持一致。切档还需要在连续点击和中途进入其他页面时保留运动状态，并保持浏览月份、选中日期和原有上下栏布局。

## Decision

扩展现有展示控制器的过渡类型，监听显示模式的赋值前通知以捕获旧端点；模式实际更新后再布局并采集新端点。原生表格先同步布局到终点，关闭其独立的隐式行高动画，避免两套运动竞争。复用设置过渡的系统无回弹 Spring（弹簧）、显示刷新驱动、圆角卡片与窗口高度、上下栏交接和资源清理，不另建定时器或在日程权限控制器中保存动画状态。

整张截图的纵向拉伸会改变字形比例，并使同一日期的两个端点在交叉淡化时重影。日程过渡以可见日期格、周分隔线和月份标题为单元，按原表格行号与列号匹配，分别保留几何位置与速度；端点采集按完整逻辑视口取样，不受起点窗口的可见高度裁剪；日期和农历使用不变的格内坐标，只有格子外框移动。日期底图在隔离合成层内做预乘透明度混合，避免相同位置的文字中途发灰；事件外观的截图混合方案由[日程标记连续形变](2026-11-06-calendar-marker-morph.md)部分取代，标记独立保留矢量运动。

连续切档把当前混合结果扁平化为单元图像，并保留每个单元的几何速度；新终点准备期间继续显示当前运动。到达终点后恢复真实日期表格。导航和关闭取消日程动画；设置和年概览在同一个展示控制器中接续容器运动。减少动态效果沿用短淡化，不保留位移缩放。

日程切档的上下栏交接和日期底图像素采样由[切档闪烁修复](../bug-fix/2026-11-06-calendar-mode-flicker.md)部分取代；设置与月年页面继续沿用原交接策略。

本决定扩展[日程按钮循环切换](2026-11-06-calendar-mode-cycling.md)，不改变其权限检测和模式持久化语义；展示驱动及连续运动的共同约束继续由[连续日历运动](../bug-fix/2026-10-24-continuous-calendar-motion.md)拥有。

日程端点的批量采样、按需年概览画布以及事件返回后的局部更新由[切档启动优化](../bug-fix/2026-11-06-calendar-mode-latency.md)部分取代，本文保留运动与形变接续的理由。

[当天日程展开](2026-11-10-inline-day-agenda.md)进一步复用本布局过渡，在原周行追加详情单元，不改变核心周索引。

## Alternatives considered

- 只为模式赋值添加 SwiftUI 动画：正文由原生表格和独立窗口拥有，不能自动同步行高、窗口与底栏。
- 直接重用设置页的整块正文交叉淡化：仍没有日期位置的连续缩放。
- 整张日期截图随容器纵向拉伸：字形比例改变，两个模式的日期偏移还会导致重影。
- 给每个视图建立独立平台动画或定时器：难以和现有窗口尺寸、反向运动及清理边界保持同步。

## Consequences

只在短过渡内保留当前可见单元的图像与运动状态，实际数据、权限和日期表格仍由原所有者管理。起止页面共用原有外壳与材质，原生文字尺寸、静态布局与现有四档高度不变。端点采集需要额外位图工作，感知时长不包含布局准备；实际流畅度仍需实机体验。

独立真实入口覆盖四至六周、四档中间态、日期格绘制、非线性节奏、位置与速度接续、深浅色与自由滚动位置、设置交接、导航和关闭清理、减少动态效果及真实显示驱动收敛。临时禁用四档动画入口的隔离副本必须因正文直接跳变而失败，证明专项能捕获原问题。按用户要求不运行全流程回归；几何采样与静态快照不替代窗口合成或物理帧率验证。
