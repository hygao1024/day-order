# Agent Note: Settings Container Transition

Status: implemented

## Problem

设置页虽然已沿用日历高度和外围材质，仍使用独立的根视图分支。进入与返回时白色面板直接替换，无法复用月视图与年概览的容器形变，也不能保证上下栏实例连续。

## Decision

运动节奏、内容淡化和中途重定向现由[连续日历运动](../bug-fix/2026-10-24-continuous-calendar-motion.md)取代：原有 220 ms 三次缓出、上下栏文字直接更新及反向直接结束不再是当前行为。本文保留快照端点、常驻容器、显示刷新驱动和生命周期约束的原始理由。

设置加入 CalendarShell 的顶部、正文、底部托管容器。CalendarSettingsView 只提供三部分内容，Shell 统一拥有圆角、外边距和布局；进入设置前记录当前自然高度，在本次设置展示期间固定总高度，返回后恢复日历原有测量。设置内容增减只改变滚动范围，偏好仍由 CalendarView 的 AppStorage 拥有。

CalendarPresentationController 区分日期缩放与设置切换，两者共用准备任务、请求修订号、临时绘制层和显示刷新驱动。设置切换只取正文快照，不抽出日期数字；最初沿用约 220 ms 三次缓出、圆角容器几何插值和正文分阶段淡化。缺少共同日期只使日期缩放降级，不阻止设置容器形变。系统减少动态效果时两种过渡均使用约 120 ms 淡化。

外层材质和上下栏保持实例与可见性，底栏随面板下沿移动。快速反向直接取消旧请求并收敛到最新页面；关闭与退出释放快照和刷新驱动。Esc 优先退出设置，再处理年概览，避免从年概览进入设置后误操作背后的页面。动画不改日期选择与浏览位置。

原生应用与弹窗外观在以 appearance 为标识的 SwiftUI task 中更新，避开视图更新轮次。同步 onChange 内切换原生外观会回传到嵌套托管视图，在设置页深浅色切换时触发布局循环；保留系统外观传播及原有偏好语义。

原生开关绑定同步时的隐式动画重入另由[设置开关布局重入](../bug-fix/2026-10-24-settings-switch-layout-reentry.md)约束，并将运行时循环诊断纳入冒烟结果；页面过渡仍使用本记录的动画策略。

此决定扩展[常驻日历外壳](../bug-fix/2026-10-24-persistent-calendar-chrome.md)和[显示同步缩放](../architecture/2026-10-24-display-synchronized-calendar-zoom.md)，取代[日期缩放过渡](2026-10-24-calendar-zoom-transition.md)中设置仅取消动画的处理。[统一设置页面](2026-10-24-rounded-settings-surface.md)的视觉与高度约束保持，由共享外壳执行。

## Alternatives considered

- 保留独立设置根视图，仅添加淡入淡出：不能得到白色容器连续形变，也无法保证上下栏实例常驻。
- 为设置另建动画控制器：会重复快照、显示刷新、减少动态效果和取消逻辑；现有驱动只需区分是否配对日期即可服务两类过渡。
- 所有页面统一固定为 430 pt：会改变月视图随详情增长的既有布局；捕获入口高度即可满足正常往返尺寸一致。

## Consequences

设置与日历共用外壳及动画生命周期，三页均不保留隐藏的完整内容树。设置切换中的日期随正文淡化，不参与日期到小月历的配对。若偏好改变了日历详情长度，返回时仍按新的日历内容调整高度。

真实入口专项记录中间几何、时间和位移进度，覆盖深浅色、材质开关、普通日期、节气、假期详情、年概览、减少动态效果、准备阶段反向、Esc 和关闭取消；检查固定高度、外壳身份、正文恢复及驱动停止。旧实现运行新增检查时因没有中间帧失败，构成负向控制。另回归设置控件和月年日期缩放。快照与主线程采样不能证明窗口服务器的毛玻璃合成、屏幕帧率或物理操作手感。
