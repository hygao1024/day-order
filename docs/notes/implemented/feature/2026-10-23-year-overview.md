# Agent Note: Year Overview

Status: implemented

## Problem

用户确认了参考 iOS 日历层级的最终设计稿：月视图采用同色上下区域、白色中心和周行横线；点击没有箭头的年月标题进入可连续跨年滚动的两列小月历。今天的圆形标记需要离横线保持足够间距。

## Decision

保留 320 pt 宽度、既有日期语义、显示开关和详情内容，月视图每个日期栈上下统一留白。深色模式映射为对应的灰阶表面。年概览替代原月份按钮页，固定顶部和底部，中间使用 NSTableView（原生表格）复用年份标题与月份行，年份标题随滚动悬浮。小月历只做公历运算，不加载全年农历、节日或网络数据。

应用模型持有概览入口、目标月份行和年份草稿；滚动位置由原生滚动视图拥有，不修改已选日期。目标之外保留请求修订号，使用户滚动离开后再次输入同一年仍会重新定位。只有点击月份才调用原有按目标月天数截断的日期选择逻辑，原因见[年月跳转记录](2026-10-23-month-jump.md)。Esc 逐层退出输入与概览，重新打开弹窗仍回到今天。

## Alternatives considered

- SwiftUI 惰性长列表与 ScrollViewReader：最初实现的真实截图出现跨多年定位为空白、目标 2048 年落到 2072 年的问题；不能依赖估算高度完成本功能。
- 一次构造全部小月历：简单，但产生两千余个小月历视图，打开与跳转成本没有必要。
- 只加载邻近年份并动态追加：可以减少视图数量，但需要自行维护插入前后的滚动锚点。原生表格已提供行复用和确定的行几何。

## Consequences

新增的 AppKit 包装仅承载年概览滚动，日期选择和偏好仍归现有模型。没有持久化迁移或新依赖。真实入口验证包括初始定位、跨年滚动、远年及同年重复跳转、鼠标点击小月历、无效输入、Esc 分层返回、上下界、每周起始和深浅色截图。其他 macOS 版本与 VoiceOver 操作仍需人工覆盖。

最初行内通过 NSHostingView 承载 SwiftUI 小月历，连续滚动仍有较高布局开销；现由[原生小月历绘制](2026-10-23-year-overview-scroll-performance.md)替代，原生列表的复用、滚动定位与导航责任保持不变。

上下固定区域的实色灰阶表面由[系统毛玻璃材质](2026-10-23-popover-material.md)替代，中间日期区与浮动年份标题使用统一实色底，浅色为白色，深色为深灰。
