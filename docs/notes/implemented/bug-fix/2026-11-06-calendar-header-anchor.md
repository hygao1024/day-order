# Agent Note: Calendar Header Anchoring During Layout

Status: implemented

## Problem

仅保证[日程切档亮度稳定](2026-11-06-calendar-mode-flicker.md)，无法阻止布局准备时的空间位移。新内容先增高，外层托管视图尚未采用新高度时，SwiftUI 默认将整页居中。隐藏转详细的真实布局曾出现 426 pt 与 582 pt 的高度差，页眉短暂上移 78 pt。原专项在准备完成后才采样，且文字像素比较采用页眉自身坐标，漏掉了整块页眉移动。

窗口尺寸通知还在托管控制器的布局回调中同步执行，触发 AppKit 布局重入；浮点首选高度与窗口分别取整后，也会使内容根视图和窗口相差半个至一个点。

## Decision

最外层 SwiftUI 根容器明确采用顶部对齐，并允许最小高度为零、最大高度无限，从而接受旧窗口的高度提议；超出部分沿下方展开。只指定顶部对齐与最大高度仍保留子内容的最小高度，无法阻止临时居中。实际自然高度继续由原有日历外壳和托管测量拥有，不新增高度偏好或动画状态。

托管控制器将尺寸通知合并到主队列后续执行，退出当前布局调用栈后只交付最新测量值；闭包弱持有控制器，原窗口显示和关闭边界继续决定是否调整可见窗口。展示控制器在设置 `preferredContentSize`（首选内容尺寸）之前统一向上取整高度，再把同一尺寸转交窗口，避免控制器根视图与窗口各自取整。日期区和标记仍以原弹簧求值，仅窗口尺寸采用一致的整点边界。

调试构建的真实外壳布局观察器在点击前接入，记录准备、运动和交接阶段的页眉屏幕矩形；快速连点及真实显示刷新回调同样检查顶部。检查入口拒绝 AppKit 布局重入日志，避免仅依赖功能退出码。设置和月年页面继续复用现有容器、过渡与清理。

## Alternatives considered

- 仅固定窗口顶部：窗口坐标未变时，其内部根视图仍可能居中移动。
- 仅声明根视图顶部对齐、保留子内容最小高度：真实准备阶段仍出现 78 pt 位移。
- 只在窗口设置尺寸时取整：控制器仍会向内容根视图提交小数首选高度，实际检查仍能捕获一个点的差异。
- 隐藏顶部或改用快照遮盖准备阶段：增加交接与点击状态，未消除根视图的位置变化。
- 放宽几何误差或只比较准备完成后的图像：无法证明用户点击后看到的第一段布局稳定。

## Consequences

现有终态布局、四档高度、胶囊形变及权限语义保持不变，只有根视图对齐和尺寸交接改变。真实专项覆盖四至六周、深浅色、四档准备至交接、快速重定向和真实刷新驱动，并复查标记形变、权限及设置过渡。旧的 78 pt 居中和一个点的尺寸差异均被新检查拒绝；此前真实布局重入日志也必须被脚本拒绝。不运行全流程；屏幕坐标、像素检查和诊断日志仍不代表所有显示器的物理帧率或桌面合成效果，最终操作手感继续由实机验证。
