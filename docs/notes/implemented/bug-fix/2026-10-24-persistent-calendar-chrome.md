# Agent Note: Persistent Calendar Chrome

Status: implemented

## Problem

月年过渡隐藏整页真实视图，再以整页位图和临时毛玻璃接管，结束后恢复目标页面。快照交叉淡化的总覆盖率即使恒定，也无法避免真实材质与临时材质交接产生跳变；复用样式代码不能保证原生视图身份不变。

## Decision

月视图与年概览共用 CalendarShell 的顶部、正文、底部托管容器。导航与详情内容在这些固定容器内更新，上下栏不淡出、不进入日期快照；正文仍按现有导航语义替换原生列表，避免把两个不可见列表同时驻留并响应模型。底栏位置跟随动画卡片下边缘，顶部和底部按当前可用高度裁剪，防止文字盖到日期区域。

展示控制器持有唯一背景材质，跟随弹窗尺寸，月年切换不重建或替换它。关闭毛玻璃时隐藏该实例、显示实色背景；设置页原先保持自己的实色表面，此部分由[统一设置页面](../feature/2026-10-24-rounded-settings-surface.md)取代。设置页加入共享外壳及双向动画由[设置容器过渡](../feature/2026-10-24-settings-container-transition.md)扩展。系统仍拥有毛玻璃与减少透明度的合成。

过渡仅缓存滚动正文，绘制圆角卡片和日期数字，暂时隐藏正文托管视图。读取终点时同步恢复正文以取样，在让出主线程前再次隐藏；完成、反向取消、设置与关闭都恢复正文和底栏布局。请求修订号继续隔离迟到任务。临时绘制层在卡片外不截获鼠标，因此常驻返回按钮和设置入口仍能中断过渡。

此决定部分取代[日期缩放过渡](../feature/2026-10-24-calendar-zoom-transition.md)的整页快照接管，以及[弹窗材质](../feature/2026-10-23-popover-material.md)的页面分别创建方式。日期端点、三次缓出、减少动态效果和原有滚动恢复语义继续由缩放记录拥有。

动画阶段的布局测量与位置更新由[显示同步缩放](../architecture/2026-10-24-display-synchronized-calendar-zoom.md)分离；上下栏和材质仍遵循本记录的常驻约束。

## Alternatives considered

- 继续调整整页快照的交叉淡化：只能修复位图内部的透明度空档，无法消除真实材质的换层。
- 抽取共享 SwiftUI 背景组件但保留两套页面分支：共享代码仍会分别创建实例，不能满足生命周期连续性。
- 将月年两页完整常驻并叠加：会保留两个原生滚动列表及其模型响应，增加滚动恢复和焦点状态的复杂度；仅共享固定外壳即可满足当前需求。

## Consequences

真实入口回归在切换开始、运行中和结束后检查外壳、上下栏、背景实例不变，上下栏及祖先不隐藏或降低透明度，并检查正文恢复。检查包含正反向、边界日期、设置和关闭取消，以及深浅色和毛玻璃开关。临时恢复整页隐藏作为负向控制，必须触发可见性检查失败。

月年头部和底部内容在目标布局准备时直接更新，不做文字交叉淡化。快照和视图身份检查不能证明窗口服务器输出的每一帧，实际桌面材质合成和物理操作手感仍需人工体验。
