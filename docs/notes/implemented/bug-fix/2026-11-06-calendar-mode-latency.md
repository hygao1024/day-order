# Agent Note: Calendar Mode Startup Latency

Status: implemented

## Problem

隐藏转详细在开始运动前同步逐日采样，并生成通用整页位图与 PDF。即使只有一条示例日程，同步按钮处理也约需 38–52 ms；事件返回后又重新准备整页，追加约 40–50 ms 的目标采样。此前[顶部锚定](2026-11-06-calendar-header-anchor.md)和像素检查能证明位置稳定，却没有约束启动阻塞。

## Decision

日期底图先同时排除一周内所有日程标记，再对周行采样一次，通过原像素网格裁出各日期格。标记排除状态在失败时也恢复；采集仅属于周行，保留[像素相位约定](2026-11-06-calendar-mode-flicker.md)，不把底栏或重复事件背景录入底图。逻辑视口中被旧窗口裁掉的末周也先刷新为当前模式，避免复用旧按钮高度。

日程专用端点复用已采集的完整周行底图，叠加本次标记后一次性合成普通位图，供初始冻结、减少动态效果和页面淡化使用；不额外截取整个原生日期区，也不从几十个日期格重新拼接或把合成延迟到动画首帧。周行临时图像仅在当前采集内存活，终点仍拥有独立位图，不增加跨过渡缓存。不提前生成年概览 PDF 画布。真正从活动模式动画进入年概览时，才在页面替换前采集所需完整画布；该画布作为一次性交接数据，不提前替换正在显示的模式画面，也不复用其他模式的旧年概览画布。

事件修订通知不再启动整页准备。准备任务会自然采集最新数据；若运动已经开始，则由原生日历协调器刷新周事件排布，展示层只重定向各格标记。底图、容器位置和速度、显示时钟不变；减少动态效果或月年返回的混合过渡仅刷新普通正文位图。模式连续切换仍合成单元底图，但已有逐格状态时不额外扁平化整个活动卡片。关闭、导航与过时读取仍由原展示控制器和事件代际边界处理，不增加长期缓存或权限访问。

本决定部分取代[正文缩放](../feature/2026-11-06-calendar-mode-animation.md)和[标记形变](../feature/2026-11-06-calendar-marker-morph.md)的端点准备与数据返回处理，保留原布局、跨日横条、非线性运动和顶部固定约束。

[当天日程展开](../feature/2026-11-10-inline-day-agenda.md)部分取代事件返回策略：详情展开时事件内容会改变布局高度，需重新准备端点；未展开时继续仅更新标记。

## Alternatives considered

- 拉长动画或提前等待日历请求：没有减少主线程采样，首帧等待和中途停顿仍存在。
- 直接删除通用快照且不处理后续页面交接：减少动态效果和切档中进入年概览仍需要相应内容，须保留普通位图并按需补齐画布。
- 数据返回后再次调用整页重定向：会重拍未变化的日期并重置容器时间，标记应独立更新。
- 从逐格动画对象合成静态端点：增加逐格透明层和运动状态的准备开销；完整周行位图已经包含日期、农历与分隔线，直接复用更便宜。
- 缓存所有月份底图或保留隐藏事件：扩大失效与隐私边界；只减少当前可见周行的重复工作。

## Consequences

普通切档仅采集起止两个端点，每周一张底图，事件返回后不重拍。性能专项挂起读取，先让真实动画运动，再恢复跨日事件，检查准备和采样次数、无额外整区截图、容器连续性与标记实际中间态。正文专项另比较冻结画面及减少动态效果终点与真实视图的像素，覆盖四档、四至六周和深浅色，防止用缺失内容换取启动耗时下降。三个月份的同步动作和平均端点采样中位数使用本机 20 ms 预算；报告单独记录异步等待与主线程更新，不把它们混算。

隔离应用恢复逐日截图、整页 PDF 或数据返回时的整页准备，专项必须分别失败。继续运行正文、标记、权限和设置的短专项，不运行全流程。表格全量行高更新仍沿用原实现，性能数字不替代正式构建、真实日历规模、显示器刷新率或操作手感验证。
