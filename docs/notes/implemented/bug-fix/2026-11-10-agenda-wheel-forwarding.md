# Agent Note: Agenda Wheel Forwarding

Status: implemented

## Problem

展开列表只有一条日程或为空时，正文没有可滚动内容，但内层滚动视图仍消费滚轮事件。鼠标悬停正文时内外两层均不移动。原专项直接调用内外层的滚动方法，没有覆盖应用按鼠标位置分发事件的组合。

## Decision

部分取代[当天日程展开](../feature/2026-11-10-inline-day-agenda.md)中内层无条件消费滚轮的约定。内层按文档高度与视口高度判断是否有溢出，容忍半点的布局舍入差异。没有溢出时沿原生响应链交给外层日历；存在溢出时仍由内层独立滚动，包括到达顶部或底部时，不将剩余滚动交给月份。

只改变内层滚轮处理的入口，不扩大鼠标命中区域、不添加全局事件监控，也不改变月初吸附或导航状态。标题与侧边空白沿用既有外层滚动路径。

## Alternatives considered

- 无论内容多少都独立消费：在短列表上没有可观察动作，形成无法滚动日历的区域。
- 内层到达边缘就转发：会让用户阅读长列表到末尾时意外移动月份，超出本次短列表问题的范围。
- 修改前两周命中区域或月初吸附：窗口坐标测试显示日期区域能够正常收到滚轮；用户进一步确认问题发生在日程正文且完全没有位移，修改这两处不能针对原因。

## Consequences

真实应用分发专项覆盖普通滚轮与精确手势、空／单条／多条日程、可见各周日期、标题、侧边与正文，并在收起后重新展开复验。记录接收者和内外层位移，检查短列表传递与长列表到底隔离。原实现在空列表正文上记录到内层收到事件、外层没有事件且双方位移为零，必须在短列表断言失败；修复后同一检查通过。

合成事件保留窗口身份与坐标，避免只调用滚动方法而绕过命中分发。该检查不覆盖所有物理设备驱动及实际惯性手感；静态布局不变，无需更新产品展示图。
