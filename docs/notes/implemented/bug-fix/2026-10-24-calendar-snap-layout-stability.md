# Agent Note: Calendar Snap Layout Stability

Status: implemented

## Problem

[月初吸附](../feature/2026-10-24-calendar-month-snapping.md)先切换周行高度、隐藏月份标题并同步布局，再执行滚动动画。日期、节日和横线在动画前突然重排，解除吸附时又恢复行高，造成可见跳变。只检查最终位置无法发现这个缺陷。

## Decision

每个月份区块在整个浏览生命周期内采用相同几何布局：其完整周行按固定视口高度和显示器像素边界均分，月份标题始终保留。吸附只移动视口，标题自然离开可见区域。核心时间线通过已有月份索引提供完整周区间，避免 UI 重新推算月份范围或维护平行索引。

移除吸附状态切换中的隐藏行、行高失效通知和强制同步布局。动画按实际经过时间插值，并在起止处缓动；新手势只取消任务和吸附状态，保留当下位置，不恢复另一套布局。每次动画更新检查导航版本、窗口可见性及当前界面，防止已离开的界面继续滚动。

此决定部分取代原月初吸附记录中的布局切换方式，停止判定、距离阈值、选择与浏览分离以及状态恢复语义继续沿用。

## Alternatives considered

- 同时逐帧改变行高、标题高度和滚动位置：可以过渡，但仍反复使长列表几何失效，需要在用户打断时协调多个状态；固定几何直接消除这一来源。
- 用截图遮盖重排：只遮住现象，并增加绘制、选择状态和无障碍同步负担，未采用。
- 所有月份固定相同周高：六周完整展示会改变弹窗高度或使四周月份留白，不符合当前整月展示要求。

## Consequences

自由浏览时不同月份的行距随周数不同，但同一月份不再随吸附状态变化。真实视图回归在整个过渡内采样行高、标题可见性、周视图身份和相对位移，并检查释放时无位置变化；旧动态布局作为负向控制应在行高不变断言失败。采样证明几何连续性和任务行为，不等价于窗口服务器帧率或物理触控板手感。
