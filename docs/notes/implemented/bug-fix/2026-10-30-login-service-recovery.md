# Agent Note: Login Service Recovery

Status: implemented

## Problem

已安装应用的签名完整性检查通过，但系统查询返回未找到登记记录，对应 `SMAppService.Status.notFound`。原控制器据此禁用开关，阻止实际登记，并直接建议重新安装。查询状态不足以判定安装损坏，也无法提供登记操作的具体失败原因。

## Decision

补充[开机自启](../feature/2026-10-30-launch-at-login.md)的恢复规则：完整应用在未找到服务时允许用户主动尝试登记，系统仍拥有最终登记状态。保留非应用包入口保护，不在启动或刷新状态时自动登记，不把缺失状态改写成成功或未登记。

操作失败时先刷新系统状态，再保存本次操作的错误，避免状态变化清除刚收到的失败原因。后续独立刷新仍可在系统状态改变时清除过时错误；用户重试时清除上一条错误。

## Alternatives considered

- 继续禁用并要求重新安装：查询失败不等于应用损坏，而且用户没有办法触发登记以获得可操作的错误信息。
- 启动时自动登记或自行写入登录项文件：越过用户主动选择，增加系统状态所有者，不符合已有开机自启契约。

## Consequences

可恢复的查询缺失不再阻断用户操作；签名或系统批准仍可能使真实登记失败或等待批准，开关只反映系统实际状态。

设置专项通过生产控件验证缺失状态下的成功、失败、重试和待批准，以及失败时系统状态改变后的错误保留。系统边界使用隔离服务，不能据此推断实际注册、系统批准或重新登录后的自动启动通过。
