# Agent Note: Calendar notification isolation

Status: implemented

## Problem

系统日期通知不保证在主线程投递。已安装的 alpha.04 在跨日通知的后台队列上直接进入 `@MainActor` 的 `AppDelegate.refresh()`，触发 Swift 执行器检查并终止进程。仅验证定时器或主线程通知无法覆盖这种长期驻留故障。

## Decision

系统跨日、时区、时钟和唤醒通知统一进入 `nonisolated`（非隔离）回调，仅以弱引用创建主执行器任务；模型与界面刷新仍由原有主执行器方法拥有。定时器和界面主动刷新保留同步调用，避免改变已有交互时序。

退出时先标记终止并移除两类通知中心的观察者，再清理界面和模型；已排队的通知任务在主执行器内检查终止状态，避免退出清理后再次刷新。

## Alternatives considered

- 仅依赖 `@MainActor` 标注：Objective-C 通知回调不会因此自动切换执行器，正是本次崩溃来源。
- 删除通知、仅依靠定时器：会延迟跨日、唤醒及时间设置变更后的日期更新。
- 使用主队列的闭包观察者：可解决投递线程问题，但需增加观察令牌的持有与清理；现有选择器入口只需明确跨执行器边界。

## Consequences

通知刷新改为异步进入主执行器，通知发送返回不表示界面已经完成刷新。真实应用回归停用定时器，从主线程及后台线程覆盖四类通知，并同时检查菜单栏、跟随今天和保留浏览选择；旧通知入口会在后台跨日用例以 `SIGTRAP`（陷阱信号）退出。运行方式及真实系统事件的覆盖限制由[界面验证参考](../../../verification.md#系统日期通知)拥有。
