# Agent Note: Complete Month Zoom Snapshot

Status: implemented

## Problem

年概览窗口比详细日程月历矮。切换时目标月历已按完整高度布局，但原生表格仍按旧窗口的可见区域复用周行；快照遍历现有子视图并按 visibleRect（可见范围）筛选日期，漏采末周。动画将缺少月端点的日期淡出，直到交还真实月历才补绘整行。

## Decision

月历端点由完整逻辑视口决定采集范围：先创建并刷新相交周行，再逐行采集完整正文位图和不含焦点日期的 PDF 背景。日期位置也按逻辑视口筛选。周行快照在视口内合成，不扩大真实窗口、不改变浏览位置、不等待事件查询。任一需要的行或快照无法创建时放弃端点，不交付缺行快照；临时隐藏日期的状态在所有退出路径恢复。

保持[单份日期网格](2026-10-25-single-calendar-date-grid.md)的独立日期绘制、行距展开和背景预绘制，只替换月端点的采集范围与来源。年概览保留原有整页 PDF 路径；日程四档切换继续使用[按周采样](2026-11-06-calendar-mode-latency.md)，不提前生成月年画布。

## Alternatives considered

- 延迟采集或等待日程返回：日期和农历已在本地，等待并不能解除旧窗口裁切。
- 提前把真实窗口撑到月历终点高度：会破坏容器从年视图尺寸连续展开的体验。
- 仅去掉日期位置的可见性过滤：未创建的末周仍缺失，农历、补位日期和事件背景也无法进入动画。

## Consequences

月端点增加少量按行采集工作，生命周期仍限于当前过渡。日程专项覆盖四至六周、深浅色，在最后一天放置今天标记和事件；末帧日期数与历法天数独立比较，并比较末周在交接前后的像素，避免用漏采的日期数作为预期值。普通月年与网格专项继续覆盖自由滚动、补位日期、红圈排除、取消和重定向。快照不证明所有设备的物理帧率。
