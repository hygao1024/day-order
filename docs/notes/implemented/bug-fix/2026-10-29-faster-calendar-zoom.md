# Agent Note: Faster Calendar Zoom

Status: implemented

## Problem

月年切换的 400 ms 弹簧在画面接近终点后仍有较长收尾，动画覆盖层期间继续拦截正文点击。主要运动时长不能代表恢复交互的总等待时间。

## Decision

将月视图与年概览双向切换的弹簧感知时长缩短到 300 ms，使主要缩放与尾部收敛一起加快。保留现有几何、速度及日期框误差阈值，避免在日期仍有可见偏差时突然交还真实页面；反向与跨设置重定向继续承接当前位置和速度。上下栏淡化与减少动态效果的节奏不变。

本决定部分取代[连续日历运动](2026-10-24-continuous-calendar-motion.md)中的月年 400 ms 节奏；[设置过渡](2026-10-29-faster-settings-transition.md)仍使用独立的 220 ms 节奏。

## Alternatives considered

- 直接在固定时刻移除动画层：可能造成终点跳动，尤其是中途反向后仍有较大速度时。
- 同时放宽静止阈值：会改变日期交接精度；先通过缩短弹簧节奏减少等待，再根据可见误差判断是否需要调整阈值。

## Consequences

300 ms 仍是感知时长，快照准备和自然收尾另外耗时。真实月年专项要求普通双向切换在 300–360 ms 的采样区间已完成至少 98% 的弹簧进度，活动采样不超过 600 ms；日期单份绘制、交接精度、自然收尾及取消检查继续适用。

采样依赖窗口所在屏幕的刷新回调；窗口失去屏幕关联时不能据此证明完整回归通过。视图快照与采样不能替代物理屏幕上的操作体验。
