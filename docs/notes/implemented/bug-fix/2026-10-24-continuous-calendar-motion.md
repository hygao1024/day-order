# Agent Note: Continuous Calendar Motion

Status: implemented

## Problem

月年与设置过渡使用 220 ms 三次缓出，约 118 ms 已完成九成位移；正文透明度也消费位移进度，旧正文约 29 ms 消失。上下栏文字直接替换，中途反向直接结束过渡，导致快速切换缺少连续性。准备阶段另有页面重建和布局交接成本，不能通过拉长动画掩盖。

## Decision

整张正文的空间变换现由[日历画布缩放](../feature/2026-10-24-calendar-canvas-zoom.md)部分取代：日期改为焦点锚点，邻月、标题、星期和日期共享相机变换，月端点附近整体衔接详细布局。本文保留其余职责与原方案的历史取舍。

展示控制器继续拥有快照、请求修订号、常驻材质、短期布局缓存和显示刷新驱动。日期与容器使用系统 Spring 的无回弹模型，月年感知时长为 400 ms，设置为 350 ms；每帧更新当前值与速度，几何误差及速度足够小后才交还真实内容，不在感知时长处硬截尾部。正文使用独立 180 ms 平滑交叉淡化，减少动态效果和不可见日期端点仍使用 120 ms 短淡化。

上下栏保留托管容器和材质，在旧内容透明快照与新内容之间交叉淡化；底栏继续跟随卡片下沿。快照不拦截上下栏按钮，正文过渡层仍只拦截卡片区域。取消、失败和完成恢复真实内容、清除文字快照并停止刷新。快照无法生成时直接交还真实页面。

新的切换请求取消过时的准备任务，但保留正在显示的运动。准备好最新终点后，日期字形与容器沿用当前值和速度，只替换目标；旧正文的透明度混合结果扁平化为一张临时图像，之后与新正文交叉淡化。日期仍按真实年月日配对、原生绘制，不把反向放大的数字烘焙进位图。该处理只保留两张正文图像和当前可见日期轨迹，不累计历史页面。准备阶段继续用请求修订号拒绝迟到结果；关闭和退出才立即注销驱动与清理状态。

月份行索引在每次重建月视图时重复遍历 1901–2100 年。索引依赖不可变的 CalendarEngine 和星期起始方式，因此由 CalendarModel 缓存当前起始方式的一份不可变索引，起始方式变化时替换。日期视图、注释缓存、滚动任务和选择仍由原来的所有者管理，不保留隐藏页面树。调试采样区分来源取样、界面刷新交接、显式布局、终点取样和索引构建；索引构建计时包含在页面准备中，不能与总耗时重复相加。

本决定部分取代[日期缩放过渡](../feature/2026-10-24-calendar-zoom-transition.md)与[设置容器过渡](../feature/2026-10-24-settings-container-transition.md)的运动曲线、淡化时序和反向处理，扩展[常驻日历外壳](2026-10-24-persistent-calendar-chrome.md)的内容交接。[显示同步缩放](../architecture/2026-10-24-display-synchronized-calendar-zoom.md)的单一驱动、目标刷新时间戳与资源清理责任继续适用。

## Alternatives considered

- 只延长三次缓出：仍从最大速度启动，透明度仍被位移进度压缩，也不能解决反向跳变。
- 直接采用 500 ms 默认弹簧作为所有页面的固定墙钟时长：系统预设可以参考，但不同页面的空间变化不同；感知时长与稳定时间也不是同一概念。
- 为每个属性建立独立平台动画：难以继续统一真实弹窗尺寸、日期绘制和底栏位置；保留现有显示刷新驱动，用系统 Spring 求值即可维护连续速度。
- 保留所有隐藏页面以消除重建成本：扩大视图、订阅和滚动状态的生命周期；仅复用不可变月份索引，继续测量剩余准备成本。
- 整体截图重放反向动画：容易让日期放大模糊，也不能承接当前几何速度；只对正文非字形内容保存当前混合结果。

## Consequences

400/350 ms 定义主要运动节奏，实际清理晚于该时刻；较大的月年位移保留细小收尾。快速改变目标可能先沿原方向减速，再转向新目标，这是连续速度的结果。开启减少动态效果时不保留位移惯性，日期的两个端点分别淡出淡入。

真实入口检查早期位移不再过急、正文与上下栏持续覆盖、自然收尾、连续反向及跨页面位置和速度接续、深浅色、星期起始、边界日期、滚动恢复、准备阶段取消、关闭与刷新静止。独立负向副本缩短弹簧节奏、清零重定向速度时，检查必须失败。检查等待真实状态并设超时，不再把固定 400 ms 当作页面已稳定的证据。

准备耗时仍受首次系统布局和机器负载影响。主线程采样与视图快照不能证明窗口服务器合成、物理屏幕无掉帧或所有显示器刷新率下的手感；这些仍需桌面体验。
