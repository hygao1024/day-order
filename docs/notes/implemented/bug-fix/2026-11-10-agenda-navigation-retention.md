# Agent Note: Agenda Navigation Retention

Status: implemented

## Problem

展开某日日程、滚动到其他月份后点击“今天”，原导航先清除展开状态。日程高度变化与导航在同次更新中出现，时间线因此禁用滚动动画并直接定位。用户需要在本次弹窗会话内保留原日期详情，关闭弹窗后才恢复默认收起状态。跨多个月浏览还会使原日期离开事件查询范围；返回途中重新取得事件并改变详情高度时，原生时间线会误取消仍在执行的导航，造成第一次点击停在中途。

## Decision

部分取代[当天日程展开](../feature/2026-11-10-inline-day-agenda.md)中导航与页面交接自动收起的决定。日期选择、月份导航、返回今天、设置与年概览切换不清除展开选择。选择日期与展开日期允许不同：返回今天只改变浏览位置及选中日期，原详情继续属于原日期与月份区块。

导航沿用原生时间线的滚动驱动。同一展开身份在导航期间收到事件更新时，真实表格同步更新周行高度，但不取消当前导航或重新准备详情动画；滚动每帧依据最新行位置计算终点。新导航、主动切换展开日期、手势、显示模式与页面交接仍使用原取消路径。日期点击以完整展开身份判断是否收起，避免返回今天后再次点击今天却关闭另一日期的详情。用户主动点击收起、再次点击展开日期、在月视图按 Esc 或切为隐藏模式时仍清空；统一弹窗关闭回调继续清空，重新打开不恢复旧详情。隐藏模式的数据及权限边界不变，不增加持久化或新的事件缓存。导航中的直接刷新部分限定了[滚动性能优化](2026-11-10-agenda-scroll-performance.md)中可见详情变化时重采动画的策略。

## Alternatives considered

- 先收起详情再启动滚动：可分开两套运动，但违反用户要求的会话内保留状态。
- 仅移除返回今天入口的收起：非动画路径还会调用日期选择，月份与页面交接也仍隐式清空，不能形成一致的会话行为。
- 返回今天时把原详情改为今天：混淆选中日期与用户展开的日期，丢失原详情上下文。

## Consequences

导航测试使用生产日期按钮、“今天”按钮和原生滚动驱动，覆盖一月一日、今天、当月其他日期的实际日程，以及从 2027 年 3 月返回 2026 年 11 月。远月场景要求原日期先离开数据范围再重新加载，另在返回末段详情已可见时注入事件更新。检查中间滚动位置、到达月份、原日程标题、展开选择及没有详情淡入过渡；生产关闭／重开入口检查默认收起。原日程专项改为验证设置、年概览与月份导航保留状态，性能专项显式清理每个独立场景的前置状态。

临时恢复返回今天入口的强制收起时，新增检查必须失败，恢复后复验。远月检查在仍因详情高度变化取消导航的实现上必须因未到达目标而失败；可见更新检查约束展示层不能在导航中接管运动。真实界面检查不替代不同设备的物理滚动手感或真实账户同步验证。事件查询仍按当前浏览月份取数，保留展开选择不意味着永久缓存该日期的事件。
