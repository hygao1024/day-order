# Agent Note: Product README and Maintenance References

Status: implemented

## Problem

README 同时承担产品介绍、界面规格和回归操作手册，尺寸、动画参数和测试产物掩盖了日序的用途与上手方式。缺少实际界面展示，读者需要理解实现说明才能判断产品是否适合自己。

## Decision

README 采用项目文档结构：简短定位与导航、快速开始、核心功能、界面预览、基本使用、数据范围和开发入口。组织方式参考 [Dify README](https://github.com/langgenius/dify)，使用客观的能力说明，避免宣传口号和场景化标题。最小构建命令直接放在首页，让使用者和贡献者无需先阅读协作规则即可启动应用。系统要求、签名状态、离线与联网边界、日期来源和放假信息不完整时的解释继续保留，因为它们影响实际使用。

沿用仓库已有 AGENTS.md 作为开发者与 AI 的入口，不另建容易混淆的 agent.md。README 保留上手所需的环境要求和最小构建命令，AGENTS.md 补充开发运行方式、基础检查和日期资源维护；长篇交互与数据契约归[日历行为与数据参考](../../../calendar-reference.md)，专项验证归[界面验证参考](../../../verification.md)。原 README 中的有效维护信息迁移到对应所有者，长期设计取舍继续由原有 Agent Notes 拥有。

产品图片复用当前应用的真实视图和现有调试截图入口，保存在 docs/images，并在验证文档中记录对应产物与更新步骤。固定日期便于核对农历、节气和休班标记；深浅色和年概览展示已有能力。图片不改绘产品内容，README 标明快照的毛玻璃呈现限制。

## Alternatives considered

- 将 README 写成产品宣传页，所有命令都下沉：快速开始需要跨文档查找，贡献者也缺少直接入口。
- 只缩短 README 并删除技术说明：容易丢失数据失败语义、专项验证入口和交互约束。
- 将所有技术段落直接堆进 AGENTS.md：会让每次加载的协作入口过长；保留必要命令和按需参考链接更适合后续维护。
- 用生成式概念图展示界面：可能虚构布局、日期或未实现功能；实际视图截图更适合作为产品事实。

## Consequences

README 服务首次访问者和准备上手的贡献者，维护文档承接深入查询。最小构建命令属于必要的就地说明，脚本仍拥有实际行为；构建入口或环境要求变化时同步更新 README 与 AGENTS.md。产品承诺变化时更新用户说明，内部实现调整则更新对应参考。界面变化需要重新生成并检查相关图片；图片是展示材料，不作为人工确认之外的自动测试结论。

视图快照能核对文字和布局，不能证明桌面毛玻璃合成、实际屏幕帧率、完整交互或所有 macOS 版本。受控绘制检查可生成真实年概览端点，但不能替代显示刷新驱动的转场回归；测试失败必须独立报告，不能因截图可用而宣称全部验证通过。
