# Agent Note: DMG and Release assets

Status: implemented

## Problem

用户需要在标签对应的 Release 附件中直接下载 DMG，而原流程仅上传 Actions ZIP 产物。正式更新源依赖 Latest 中的签名清单，云端没有 Sparkle 私钥，不能将缺少清单的正式版本自动公开。

## Decision

部分取代[标签 ARM64 构建](2026-10-31-tag-arm64-build.md)的产物与发布范围，保留其版本编号和源码检出规则。使用 macOS 自带 hdiutil 生成包含应用和 /Applications 符号链接的压缩 DMG；只读挂载后验证实际应用、快捷入口并卸载。ZIP 继续服务自动更新和直接解压安装。

构建任务保持只读，独立发布任务只在完整产物成功后取得仓库写入权限。先上传草稿并核对远端摘要，再将预发布标签公开；正式版本停留在草稿，签名清单继续由本机私钥持有者负责。恢复仅允许替换尚无签名清单的草稿附件，拒绝修改已公开版本或使既有清单失效。

## Alternatives considered

- 继续只上传 Actions 产物：无法满足 Release 页面直接下载安装包的需求。
- 引入第三方 DMG 排版依赖：当前只需应用与安装入口，系统工具即可完成，避免额外供应链与维护成本。
- 所有标签自动公开：正式版本缺少 appcast.xml 会破坏固定更新源。
- 将 Sparkle 私钥上传云端：不是生成 DMG 所必需，不扩大密钥保管范围。

## Consequences

预发布版本可以直接下载，但不进入正式自动更新。正式发布仍需补齐签名清单并人工公开；代码临时签名与更新签名都不能替代 Apple 公证。发布失败可能留下可恢复草稿；已公开标签重跑发布会失败，需要新标签。打包验证覆盖真实挂载与代码签名，发布边界测试覆盖坏校验值和公开附件保护，云端执行验证真实上传与预发布状态；完整 GUI 和 Gatekeeper 行为仍需另行验证。

操作契约由[软件更新与发布](../../../app-updates.md#标签自动构建)拥有。
